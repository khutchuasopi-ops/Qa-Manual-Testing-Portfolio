# BUG-002 — Unable to Return from Operator Mode

## Bug Information

| Field           | Details                                                                   |
| --------------- | ------------------------------------------------------------------------- |
| Bug ID          | BUG-002                                                                   |
| Title           | User cannot clearly return to the AI chatbot after entering operator mode |
| Severity        | High                                                                      |
| Priority        | High                                                                      |
| Status          | Open                                                                      |
| Testing Type    | Manual / Functional / Exploratory                                         |
| Area            | Operator Handoff / Conversation State                                     |
| Reproducibility | Reproducible                                                              |

---

## Summary

After the user requests a human operator, the chatbot enters an operator-related state.

When the user subsequently attempts to return to the AI chatbot, the conversation remains in the operator state instead of providing a clear way to resume AI interaction.

This creates a state-management and recovery issue within the conversation flow.

---

## Environment

* **Application:** Confidential AI-Powered E-commerce Chatbot
* **Platform:** Web
* **Testing Approach:** Manual Testing
* **Testing Type:** Functional / Exploratory
* **Browser:** Web browser
* **Environment:** Available test environment

> Exact browser version and execution date were not recorded during the original test session and are therefore not claimed here.

---

## Preconditions

1. The chatbot is available.
2. A user can start a conversation with the chatbot.
3. The application supports requesting a human operator.
4. The user can send additional messages after the operator request.

---

## Test Data

Example operator request:

```text
Connect me to an operator
```

Example attempt to return:

```text
Never mind. Can you return me to the chatbot?
```

---

## Steps to Reproduce

1. Open the AI e-commerce chatbot.
2. Start a conversation.
3. Send a request to connect with a human operator.
4. Confirm that the chatbot changes to the operator-related state.
5. Send a follow-up message indicating that operator assistance is no longer required.
6. Request to continue the conversation with the AI chatbot.
7. Observe the chatbot state and response.

---

## Expected Result

The application should handle the user's request to return to the AI chatbot according to the intended conversation design.

If returning to AI interaction is supported, the chatbot should:

* clearly exit the operator-related state
* resume AI conversation
* preserve relevant conversation context where appropriate
* provide a clear confirmation to the user

If returning is not supported, the interface should clearly communicate that limitation and provide an appropriate alternative.

---

## Actual Result

After the user attempts to return to the AI chatbot, the conversation remains in the operator-related state.

The user does not receive a clear recovery path for continuing the conversation with the AI chatbot.

---

## Impact

This issue may:

* prevent the user from continuing the intended conversation
* create confusion about the current chatbot state
* make the conversation appear stuck
* reduce user control over the chat experience
* require the user to restart the conversation

The issue is particularly important because operator handoff represents a state transition in the core chatbot workflow.

---

## Severity

**High**

The issue can prevent the user from continuing the AI conversation after entering an operator-related state.

---

## Priority

**High**

A clear recovery path is important for maintaining a predictable and usable customer-support experience.

---

## Reproducibility

**Reproducible during manual exploratory testing.**

The issue was observed after transitioning from AI chatbot interaction to operator-related state and attempting to return to AI interaction.

---

## QA Assessment

This is classified as a **functional state-management defect**.

The primary concern is not the operator handoff itself, but the lack of a clear and functional transition back to the AI conversation.

State transitions should be explicitly defined and tested because incorrect state handling can leave users without a clear way to continue their task.

---

## Recommendation

Possible corrective approaches include:

1. Define the expected state transition between AI and operator modes.
2. Provide an explicit action for returning to AI chat if supported by the product requirements.
3. Clearly communicate the current conversation state to the user.
4. Preserve relevant conversation context when returning to AI interaction.
5. Add return-from-operator scenarios to regression testing.
6. Test additional state transitions such as minimize, reopen, refresh, and new conversation.
