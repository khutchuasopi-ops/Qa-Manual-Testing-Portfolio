# BUG-003 — Invalid Email Accepted During Login

## Bug Information

| Field                 | Details                                             |
| --------------------- | --------------------------------------------------- |
| Bug ID                | BUG-003                                             |
| Title                 | Invalid email credentials are accepted during login |
| Module                | Authentication / Login                              |
| Severity              | Medium                                              |
| Priority              | High                                                |
| Status                | Open                                                |
| Test Type             | Functional / Negative Testing                       |
| Related Test Case     | TC-002                                              |
| Related Test Scenario | TS-002                                              |

## Description

The login functionality accepts invalid email credentials and redirects the user to the home page instead of rejecting the login attempt.

## Preconditions

* The e-commerce web application is accessible.
* The login page is available.

## Steps to Reproduce

1. Open the e-commerce web application.
2. Navigate to the login page.
3. Enter an invalid email credential.
4. Enter the corresponding password value used during the test.
5. Submit the login form.
6. Observe the result.

## Expected Result

The system should reject invalid login credentials and display an appropriate validation or error message.

## Actual Result

The invalid email credential is accepted and the user is redirected to the home page.

## Impact

The behavior may allow an invalid authentication attempt to appear successful and can create confusion about the user's actual authentication state.

## Evidence

Evidence can be attached when available, such as:

* Screenshot of the entered invalid email.
* Screenshot of the resulting page after submission.
* Screenshot of any displayed login or validation message.

## Regression Testing

After a fix, verify:

* Valid credentials allow login.
* Invalid email credentials are rejected.
* Invalid password credentials are rejected.
* Empty login fields are validated.
* Malformed email formats are rejected.
* A user cannot access protected functionality after logout.
* Login state behaves correctly after page refresh.

## QA Note

This defect was identified during negative testing of the login functionality. The report describes the observed behavior without assuming a backend or authentication implementation root cause.
